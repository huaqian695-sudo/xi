## 代码结构

### 入口

| 文件 | 干什么 |
|---|---|
| `main.py` | `main()` 启动：校验菜谱 → 建库 → 加载场景 → 起天气/提炼两个后台循环 → 起通道。`handle()` 处理一条消息，**拆成四步**：`_make_turn`（纯构造，出错就崩）→ `_touch_person`（认人，失败不挡回复）→ `_think`（跑前置链，失败回兜底话术）→ `_record`（记账，失败不挡回复） |
| `cli.py` | `status` / `doctor` / `last` + 4 个占位（think/memory/dsh/apply） |

### 场景（6 个，每个 = scene.py + recipe.yml）

| 场景 | 干什么 |
|---|---|
| `chat.reply` | 纯文字出话，菜谱 18 个块 |
| `chat.image` | 带图出话，多一个图片指令块 |
| `chat.qa` | 查证：调工具 → 要求模型输出结构化 JSON → 解析成 facts → 写库 |
| `label` | 消息标注，4 秒软截止，超时降级 `uncertain` |
| `memory.extract` | 记忆提炼，输入一批对话，输出 JSON 数组 |
| `tick` | 心跳：她自己醒着的一刻，输出内心 / 情绪 / 要不要说话 |


场景现在分两种写法：

- **菜谱场景**（`chat.reply` / `chat.image` / `chat.qa`）继承 `RecipeScene`，只声明 `name`。
  四步流程在基类里，改归档方式或补 usage 只改一处，不用改三遍。
- **自写场景**（`label` / `memory.extract`）保留自己的 `run`：`label` 有 4 秒软截止，
  两个都不把 `tools` 交给引擎。

每个场景类还可以声明两件事，`doctor` 拿它们跟菜谱对账：

| 声明 | 含义 | 今天谁不一样 |
|---|---|---|
| `recipe_sections` | 消费菜谱里的哪几段 | `chat.qa` 只消费 `("块", "用户")`，不拼历史 |
| `accepts_tools` | 会不会把工具箱交给引擎 | `label` / `memory.extract` 为 `False` |

`RecipeScene.build_messages` 直接读 `recipe_sections`，所以"声明拼哪几段"和"实际拼哪几段"不会对不上。

### 核心机械

| 文件 | 干什么 |
|---|---|

## 一条消息的完整流程

```
通道读一行 → Incoming
  ↓
_make_turn        生成 turn_id、组 Turn（纯构造，出错就崩）
  ↓
_touch_person     建/更新 people 档案（失败不挡）
  ↓
_think → chain.run
  ├ quick_judge   规则抢答（"哈哈"→不查，"天气"→查），命中就不问模型
  ├ label 场景    没抢到才问模型，4 秒软截止，超时→uncertain
  ├ 要查证 → chat.qa
  │    工具循环（weather/web_search/web_fetch）
  │    模型输出结构化 JSON → 解析成 facts → 写 4-facts → 交给 reply
  └ 出话 → chat.reply / chat.image
        assemble：system 块 + 历史多轮 + 当前 user
        历史展开成 user/assistant 轮次，群聊带发言人名字
        工具循环 → 模型 → 回复
  ↓
_record
  ├ turns.jsonl（一轮一行：谁说的、哪条链、标签、拼了哪些块、投递状态）
  ├ runs.jsonl（每次调用：完整 prompt、输出、usage）
  ├ tools.jsonl（每次工具调用）
  └ organize.from_turn → interactions（他一句、她一句、她的动作，都按 person_id 记）
  ↓
通道打印
```

**后台**：03:00 提炼记忆，07:00 预取天气。

| 文件 | 内容 |
|---|---|

| `runs.jsonl` | 一次调用一行：**调用一完成就落，不等整轮**；ts、scene、tier、provider、model、**duration_ms**、**完整 prompt**、输出、**reasoning**、**finish**、**note**、**tool_calls**、usage |
| `tools.jsonl` | 一次工具调用一行（同样实时落）：tool、args、ok、**duration_ms**、output（截 2000 字） |
| `events.jsonl` | 启动 / 断连 / 异常 / 后台任务 / 提炼批次（`extract`）/ **`turn.start`（收到消息立刻记）/ `call.start`（每次调用开工前记）** |

**两条刻意的取舍**（2026-11-05 定，别当 bug 修）：

- **平台和外部账号不进原始层**：核心只认 `person_id`，映射在 `people.db` 的
  `bindings` 表。代价是同一个人的多个平台号之间无法区分"这条是哪个号发的"。
- **图片/文件只存路径引用**，不存副本。代价是清理缓存/移动文件后，老记录会指向
  不存在的路径（读取方已容错，不会崩，但回放会缺料）。

`turns.result` 的 `usage` 是**整轮合计**（多轮工具循环也累加），`runs.usage` 是单次。

## 关键机制（容易忘的）

| 机制 | 规则 |
|---|---|
| **历史与记忆错开** | 历史管最近 3 天（当前会话）；记忆**跳过最近 3 天**（那些历史里有）；主动记的（`manual*`）例外 |
| **记忆带日期和归属** | 每条是 `[2026-10-01] 浅华不吃辣`，库里另存 `speaker_channel/user_id/name` |
| **核心不认识平台** | 消息里只有 `person_id`；平台账号在通讯层 `bindings` 表里翻译 |
| **身份只认号** | `0` = 汐本人，`1` = 主人，`2+` = 别人。交互流里没有"他/她"这种文字标签，名字统一从 `people` 表查，代码里不写死人名 |
| **主人固定 1 号** | `config/core.yml` 的 `owner.id`；各平台谁是他，在 `owner.bindings` 里配 |
| **动作块** | 上一轮她调过什么工具，拼成一块"这是真的执行记录"——否则她会把自己的真实行为当成编造 |
| **拼块顺序** | 稳定的在前、易变的在后。「此刻」每轮必变，压到最后一块数据（在「输出规则」之前），否则前缀缓存从它那儿断开 |
| **工具清单现生成** | 菜谱写 `工具箱: 封装`，清单从 `ToolSpec` 现生成；以前手写在常量里，加工具没人改，`send_file` 就一直没被写进去 |
| **三层工具过滤** | 菜谱说用哪个箱 → `persona.yml` 的 `allow` 白名单 → 全量箱不受 allow 限制 |
| **工具结果三件事** | 带来源、带时间、失败分类型（连不上 / 没找到 / 名字不对） |
| **提炼每天一次** | 03:00，启动补跑，分批 60 轮，整批一个事务 |
| **天气预取** | 07:00，三城 × 两天，写事实库，保质期到当天 23:59 |
| **失败隔离** | 前置链失败回兜底话术；记账失败照常回话；两者都写 events，`cli status` 能看 |
| **超时分层** | 单次 HTTP 超时 × 重试次数 + 间隔 **<** 整场景超时。卡住的调用先自己失败、留下 `ok=false` 的 runs，场景还有余量回兜底话术。`label` 例外（自己有 4 秒软截止 + 规则兜底）。`test_timeouts.py` 守着这条 |
| **心跳的检索词** | 不是字面量「最近」：用最近 3 条内心 + 最后一句他说的，拼成查询再去搜记忆。心跳没有当前消息，只能从「她刚在想什么」里找线索 |
| **状态块** | 读 `6-state/state.json`（M4 之前没人写，所以只有一行）。"这次已经醒着多久"**始终有**——它来自进程启动时刻，不依赖文件 |
| **排查留痕** | 每次模型调用、每次工具执行各记 `duration_ms`；提炼成功也记一条 `extract` 事件；每次记忆检索写 `memory_hits`（没命中也留一行，`memory_id` 为空） |
| **依赖只朝一个方向** | `support → core`，`core` 不许 import `support`。唯一豁免是 `core/engine.py::default_tool_executor` 的延迟导入（为 `Engine(cfg)` 兼容），生产路径由 `main.py` 显式注入执行器。`support/tests/test_boundaries.py` 静态扫 + 运行时扫，多一处就红 |
