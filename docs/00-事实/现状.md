## 一句话

一个能聊、有记忆、会提炼的终端版汐。她还没手（不能上网/发文件），也没接 QQ。

身份/会话已经按多平台设计好了：`(channel, chat_type, chat_id)` 管"在哪儿说话"，
`(channel, user_id)` 管"是谁"，名字只当别名存快照。

```bash
python3 main.py                          # 真模型，正式数据
XI_USE_MOCK=1 python3 main.py            # 假模型，验收链路用
XI_STORE=store/_dev python3 main.py      # 试验库，正式数据一点不沾
python3 cli.py status           # 状态
python3 cli.py last             # 刚才那一句走了什么
python3 cli.py doctor           # 自检
```

## 数据的加工链

```
raw/turns.jsonl（真相：一轮一行，含他说+她回）
      │  core/organize.py :: from_turn   同步、幂等、容错
      ▼
interactions（对话稿：拆成一条一句，带 channel/说话人）
      │  scenes/base.py :: fetch_history  展开成 Role 轮次
      ▼
messages（多轮：system + user/assistant… + 当前 user）
```

main 只写 raw，不再直接写 interactions——那份是整理出来的。

## 全景：一条消息走过哪些文件

```
终端
 │  support/channel/stub.py       读一行，包成 Incoming
 ▼
main.py :: handle
 │  core/clock.py                 生成 turn_id、时间戳
 │  core/chain.py :: run          前置链
 │    ├ core/chain.py :: quick_judge     规则抢答（命中就不问模型）
 │    ├ scenes/label/scene.py            问模型要标签（0.9s）
 │    └ 按标签分流
 │        ├ scenes/chat_qa/scene.py      要查证 → 先查（现在还没有工具）
 │        └ scenes/chat_reply/scene.py   出话（有图则 chat_image）
 │            ├ scenes/base.py :: assemble      按菜谱取块、拼 messages
 │            │   └ scenes/base.py :: fetch      六种块 → 人设/状态/记忆/事实/常量/当前
 │            ├ core/engine.py :: run            按档位发模型
 │            │   └ core/llm.py :: LLM           真 HTTP 调用
 │            └ 写成品留档
 ▼
main.py 记账
 │  core/rawlog.py                四本账（后台队列）
 │  core/repo.py                  交互流（他说的、她说的）
 │  core/repo.py :: upsert_label  标签落库
 ▼
终端打印

（后台，每 60 秒）
pipeline/extractor.py :: loop
 │  core/repo.py :: since_id      取游标之后的新对话
 │  scenes/memory_extract/scene.py  让模型压成几条
 │  core/repo.py :: add_memories_bulk  整批入库
 │  core/embed.py                 补向量
 │  写游标
```

## 逐个文件

### 入口

| 文件 | 干什么 | 怎么实现的 |
|---|---|---|
| `main.py` | 启动 + 一轮处理 | `main()` 读配置→校验菜谱→建库→加载场景→起提炼循环→起通道循环。`handle()` 是核心：建 Turn → 调 `chain.run` → 写四本账 → 写交互流 → 返回要发的话 |
| `cli.py` | 运维命令 | `status` 数档位/场景/账本；`doctor` 用 `validate` 查配置和菜谱；`last` 读最近一跳 turns 摊开给人看；`think/memory/dsh/apply` 是占位 |

### 场景骨架

| 文件 | 干什么 | 怎么实现的 |
|---|---|---|
| `scenes/base.py` | 场景基类 + 注册表 + 上下文 | `load_scenes()` 扫 `scenes/*/scene.py`，用 importlib 动态加载，找 `Scene` 子类实例化，按 `name` 注册。`assemble()` 是四步里的第二三步：遍历菜谱的 `块`/`用户`，判断 `当`，调 `fetch`，拼成 system/user。`SceneContext` 给场景所有能力：`recipe()` 读菜谱、`when()` 判条件、`fetch()` 取块、`archive()` 写成品、`save_label()`/`save_facts()` 落库 |
| `scenes/constants.py` | 常量块 | 11 条写死的 prompt 段落（陌生人警告、标注任务、提炼任务、图片指令…）。菜谱里写 `常量: 标注任务`，`fetch` 从这里取 |

### 五个场景（每个 = scene.py + recipe.yml）

| 场景 | 干什么 | 怎么实现的 |
|---|---|---|
| `chat.reply` | 纯文字出话 | 35 行：读菜谱 → `assemble` → `engine.run` → 归档 → 返回。菜谱里 17 个块（人设、此刻、情绪、内心、状态卡、记忆、事实、工具、输出规则…） |
| `chat.image` | 带图出话 | 跟 reply 同一套料，多一个「图片指令」常量，user 里挂图 |
| `chat.qa` | 查证 | 同四步，但返回的是 `{question, facts[], not_found[]}` 而不是话；末尾调 `ctx.save_facts()` 落库。**现在还没有工具，facts 恒空** |
| `label` | 消息标注 | 真模型问标签，`asyncio.wait_for` 4 秒软截止，超时/解析失败一律降级成 `uncertain`。结果写 `labels` 表 |
| `memory.extract` | 记忆提炼 | 输入是一批交互（不是一条消息），输出 JSON 数组，`_clean()` 做字段校验（kind/status 枚举、content 长度） |

### 核心机械

| 文件 | 干什么 | 怎么实现的 |
|---|---|---|
| `core/chain.py` | 前置链：标签→查证→出话 | `quick_judge()` 先用规则抢答（"哈哈""晚安"直接 no，命中"天气""多少钱"直接 yes），抢不到才调 label 场景。`run()` 按 `need_facts` 决定要不要先跑 qa，再按有没有图选 reply/image。**四种走法**：无图/有图 × 查/不查 |
| `core/config.py` | 读配置 | 带 mtime 缓存：文件没改不重读、改了下一条立即生效。`tier()` 会叠人格覆盖（`/model` 改的就是这里）。`override()` 给测试用，整份替换 |
| `core/clock.py` | 时间 | 全部日期算术收一处：`iso()`、`day_dir()`、`stamp()`、`time_slot()`、`new_turn_id()`、`in_quiet_hours()`（支持跨零点静默） |
| `core/rawlog.py` | 原始层写入 | 后台线程 + 有界队列（10000）。`append()` 只入队，永不阻塞、永不抛。队列满时 `events/tools` 直接丢，`turns/runs` 绕开队列同步写。`flush()` 等真正写完并返回 bool |
| `core/db.py` | 五个库 | 建表 SQL 全在这；`connect()` 开 WAL + busy_timeout；`ensure_all()` 启动时建齐 |
| `core/repo.py` | 数据读写（最大的文件，507 行） | 交互流：`add_interaction`/`recent_messages`/`since_id`/`open_session`。标签：`upsert_label`。事实：`put_facts`（同源替换、异源冲突两条都留）、`active_facts`（过滤过期/被替换）。记忆：`add_memories_bulk`（一批一事务）、`search_memory`（关键词 + 向量混合）、`similar_exists`（判重 0.75） |
| `core/llm.py` | 真模型客户端 | OpenAI 兼容。从 `providers.yml` 取地址和 `key_ref`，key 走环境变量 → `~/.dsh/.credentials.yaml` → `~/.config/siliconflow/key`。必须带 User-Agent（网关前有 Cloudflare，默认 UA 会 403）。失败重试 2 次，4xx 不重试 |
| `core/engine.py` | 按档位发模型 | `run()` 查档位 → 建 LLM → `asyncio.to_thread` 包同步调用 → 返回 `{output, calls}`。calls 里带 prompt 全文，供原始层存 |
| `core/embed.py` | 向量 | bge-m3（硅基流动，1024 维，0.25s）。`embed_texts()` 批量、`cosine()` 余弦、`pack/unpack()` 存 float32 省空间。失败返回 None，调用方退回关键词 |
| `core/parsing.py` | 从模型输出里挖 JSON | 三级：直接解析 → 剥 ```json 围栏 → 抓第一个 `[`/`{` 配平括号。挖不到返回 None |
| `core/validate.py` | 菜谱校验 | `validate()` 查已注册场景（名字/档位/工具箱/产品号/块类型/谓词/常量）；`validate_all_recipes()` 连孤儿菜谱一起查；`orphan_recipes()` 提示有菜谱没代码的 |

### 数据处理

| 文件 | 干什么 | 怎么实现的 |
|---|---|---|
| `pipeline/extractor.py` | 60 秒提炼循环 | `read_cursor()` 读上次到哪（自增 id，不是时间戳——同一秒多条会漏）；`since_id()` 取新交互；`format_batch()` 按附录 F 格式排版；调场景提炼；**整批一个事务**入库；`write_cursor()` 推进。向量单独批量补，失败不影响入库 |

### 通道

| 文件 | 干什么 | 怎么实现的 |
|---|---|---|
| `support/channel/base.py` | 通道接口 | `Incoming` 数据结构 + `receive()`/`send()` 两个方法。接 QQ 就是实现它（M6） |
| `support/channel/stub.py` | 假前台 | `input()` 包成 `asyncio.to_thread`，`#图` 前缀模拟带图 |
| `support/mock_llm.py` | 假模型 | 回一句"（假模型收到：N 条消息、M 字）"。M0/M1 用它证明链路通 |

## 数据分两处

| 位置 | 是什么 | 进 git |
|---|---|---|
| `store/` | 她的正式记录 | 只有人设 |
| `store/_dev/` | 试验场，随便删 | 不进 |
| `store/processed/1-persona/` | **人设**（不跟数据走） | 进 |

切试验库：`XI_STORE=store/_dev python3 main.py`。

人设单独拎出来，是因为它是**源码**不是数据：手写、要版本管理、跟代码一起演进。
放在数据根里会被 `.gitignore` 的 `*.db` 规则连累，也要靠一堆 negation 才能提交。

## 配置文件（5 份）

| 文件 | 里边是什么 |
|---|---|
| `config/core.yml` | 路径、日志、调度（30 分钟心跳 / 03:00 整理）、预算、通道、隐私闸、`llm.use_mock`、`daemon.extract_loop` |
| `config/providers.yml` | 两家服务：opencode（LLM 网关）、siliconflow（向量/小模型）。只写 `key_ref` 名字，不写 key |
| `config/tiers.yml` | 8 个档位。label 用硅基流动 Ling-mini（0.9s），其余用 opencode 的 deepseek-v4.1-flash |
| `config/services.yml` | 4 个能力：embed（bge-m3）、tts、draw、vision |
| `config/personas/xi/persona.yml` | QQ 号、主人号、作息、主动频率、工具箱白名单、`overrides`（`/model` 改这里）、记忆参数 |
