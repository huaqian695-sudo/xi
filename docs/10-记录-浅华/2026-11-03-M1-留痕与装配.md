## 偏差

1. **标注是规则版**（`core/chain.py:guess_label`），不是模型。M2 换成 `label` 场景，只需要换这一个函数。
2. **查证场景还没有工具**，`facts` 恒为空数组。所以 `产品:4.事实块` 和 `常量:事实纪律` 两个条件块现在永远不拼——四种走法里的"查"只走到了"调 qa"，没走到"拿到结论"。
3. **`tick/` 只有菜谱**，注册表跳过它。`doctor` 会提示，不算错。
4. **图片是假的**（`#图` 会塞一个 `(假图)` 字符串），真像素在 M3。

## 一个值得记的现象

`cli.py last` 显示"语气=低落"，但他说的是"这里天气如何"。

查出来原因了：情绪判断里的低落词有「气」，而"天**气**"正好包含它——子串匹配撞上了。

```
elif any(w in text for w in ("烦", "累", "难受", "崩", "气")):
    cue = "低落"
```

**这是规则版的典型病：用子串匹配代替理解，总会在想不到的地方撞车。**
M2 换成模型标注后这类问题自然消失，所以规则版只配当过渡——但它也从反面说明了一件事：
把「判断」交给模型、把「流程」交给代码，这个分工是对的。规则能写清楚的都是流程，
写不清楚的（对方什么语气）就该让模型看。

## 补记：真实语料回归（23:05）

浅华提了一条：测试可以从隔壁项目（`~/deepseek/xi-core`）读真实聊天记录，增强可信度。
已写进大纲 §9.8，并当场落地。

**做法**：

- `support/tests/fixtures.py`：只读打开旧库（`mode=ro`），取「他说的」最近若干条，
  跳过斜杠命令和超长消息
- `support/tests/test_legacy_corpus.py`：把这些真消息喂给新链路，跑一遍

**三条不变量**（测的是这个，不是回复内容）：

1. 不崩
2. 每条都有非空回复
3. 场景链以 `label` 开头、至少两段
4. 标签分布不是常量（全 yes 或全 no 说明规则没在判断）

**第一次实测**：20 条真实消息，`no 18 / uncertain 1 / yes 1`。

这个分布本身是个有用的数字：**真实对话里九成不需要查证**。也就是说 qa 的触发率很低、
成本可控；反过来，如果哪天这个比例突然飙升（比如 30% 都在查），就说明规则或提示词跑偏了。
以后可以拿它当"qa 有没有被滥用"的体检指标。

**三条规矩**（也写进大纲了）：只读不复制、库不在就 skip、只打印分布不打印原文。
第二条是为了让测试能独立跑——不能因为隔壁项目删了就红一片。

## 更正：这条规则是"素材优先"，不是"额外冒烟"（23:10）

一开始我把浅华的意思理解成了"顺带跑一遍真实语料做冒烟"，写成了 §9.8 的补丁。
他的原意是：**以后写测试用例，输入就优先从真实语料里挑**——这是方法论，不是补充测试。

已重写 §9.8：素材分三档，按优先级用——

1. **真实原文**（运行时取，默认首选）
2. **真实语料的形状**（手写但照着真话写：半句、省略、错字、表情）
3. **边界值**（空串、超长、纯符号——这类真实语料里没有）

并写了一条"默认动作"：写新测试时先去 `load_legacy_messages()` 看有没有合适的，
没有再按第二档写，只有测边界才用第三档。

清单的贯穿那条也同步改了。

**为什么这条值得单独立规矩**：手写的句子太规整。测"明天天气怎么样"能过，不代表
"明天要下不下雨啊那个"能过。真实语料里有 1135 条消息，那些才是她真正见过的话。
