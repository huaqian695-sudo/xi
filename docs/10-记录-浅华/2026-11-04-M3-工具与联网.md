## 两个发现

### 1. 中文搜索的相关性过滤，一开始是废的

第一版 `_relevant` 把「明天北京天气」当成**一个整串**去标题里找，必然找不到——
标题是「北京天气预报」。结果所有结果都被判成"不相关"，搜索一直失败。

**修**：中文按 2–3 字片段切（跟记忆检索一个思路），命中够数才算相关。

实测：

| query | 结果 |
|---|---|
| 明天北京天气 | bing，3 条 |
| DeepSeek 新模型 | bing，3 条 |
| 今天有什么新闻 | 降级到 so.com，1 条 |

### 2. 她会重复查

问「我不吃什么」，她连调 **3 次** `memory_search`，换了三种问法；
问天气，调了 **6 次** `web_fetch`，把 open-meteo、wttr.in、空气质量都翻了一遍。

第一次就够用了，后面是浪费。可能的原因：

- 模型不确定"查到的够不够"
- 工具结果没有告诉她"够了"

**候选修法**（先记着）：
- 工具结果末尾加一句"已查到，别重复查"
- 步数上限从 6 降到 4
- 同一工具连续调用相同参数时直接拦

## 补记：天气预取 + 记忆时间标签（19:50）

浅华提了两条：天气太常用，改成预取；记忆要带时间。

### 天气预取

`pipeline/weather.py`：每天 07:00 查**洛阳 / 北京 / 安阳**今明两天，写进事实库。
启动时也先补一次——别让第一问空手。

存的是事实块（`4-facts`），因为它本来就是"带来源、带保质期的结论"：

```
北京 2026-11-05 有雾，4.7~16.2℃，降水概率 0%   （过期 2026-11-05 23:59）
洛阳 2026-11-04 阵雨，11.8~16.2℃，降水概率 100%
```

新的 `weather` 工具：

```
问 → 查库 → 有 → 秒回，标「来自今早的预取」
              ↳ 没有 → open-meteo 现查 → 存库 → 标「刚查的」
```

实测：

```
他：洛阳明天天气怎么样
她：明天洛阳多云，10.7 到 21.4 度，不下雨。
    早晚有点凉，出门还是套件外套更稳妥。
```

工具账显示来源是预取库，不是现查。

### 记忆带时间

拼进 prompt 的记忆，每条前面加了记录日期：

```
- [2026-10-01] 浅华不吃辣
- [2026-11-03] 浅华要求汐以后不要给他推荐辣的
```

理由是浅华说的：**时间是记忆的一部分**。"今天说的"和"上个月说的"分量不一样。
之前只给内容，模型没法判断新鲜度。

### 封装箱从 8 件变 9 件

加了 `weather`。剩下没做的：`send_file`、`ask_dsh`（M5）、`qq_do`（M6）。

## 补记：照 DSH 的做法提高工具准确性（20:30）

浅华说参照 DSH 的源码。看完了 `dsh-agent-loop` 和 `dsh-agent-tool-presentation`，
结论是：**DSH 的严谨在"调度"上，不在"结果准不准"上。**

### DSH 做了什么

| 做法 | 说明 |
|---|---|
| 并行执行 | 独立的工具调用同时跑（上限 10），"独占"的才串行 |
| 结果按模型顺序提交 | 跑是并行的，写进历史按模型请求的顺序 |
| 配对完整 | 中止时给没启动的调用补合成错误结果，历史不留缺口 |
| 错误码 | `TOOL_NOT_STARTED` / `TOOL_OUTCOME_UNKNOWN` / `ABORTED_BEFORE_DISPATCH` |
| 呈现方式 | native（每个 schema）或 ptc（只给 run_code + SDK）二选一，每个 agent 只声明一次 |

**它没有"重复调用检测"**——因为那不是它的痛点。

### 我们照"准确"改了三点

**1. 工具箱说明写清"什么时候用哪个"**

之前只说"你可以用搜索、看网页、翻记忆…"，没说边界。现在：

```
- weather：查天气。今明两天的数据每天早上已经备好，直接读，最快最准。
  别自己拼天气接口的 URL——那要猜经纬度，容易错。
- web_search：搜资料。写关键词，别写整句；找到链接再决定要不要看全文。
- web_fetch：直接打开网址或接口。有固定接口的数据优先用它。
查完要说清楚三件事：查到了什么、从哪来的、什么时候查的。
```

**这一条最见效**：改之前问天气，她自己拼 open-meteo 的 URL（要猜经纬度，容易错）；
改之后只调 `weather` 工具。

**2. 结果带来源和时间**

```
（api.open-meteo.com · 抓取于 11-04 20:28 · 1200 字）
{...正文...}
```

**3. 天气标注"预报会变"**

```
安阳 2026-11-05 阴，7.2~21.5℃，降水概率 0%（open-meteo，今早预取；预报会变，出门前再看一眼）
```

### 重复调用：按浅华的意思不治了

他说"多查几次无所谓，主要是查得准"。所以并行执行也没做——那是速度问题，不是准确问题。

### 实测

```
他：安阳明天天气怎么样
她：安阳明天阴天，7.2 到 21.5℃，降水概率 0%（open-meteo，今早预取）。
    早晚温差有点大，中午倒是还行，出门带件外套吧🐳

他：洛阳今天下不下雨
她：下，洛阳今天阵雨，降水概率 100%，11.8~16.2℃。
    带伞哦，别淋成落水鱼🐳
```

工具账里只有 `weather`，没有她拼的 URL。来源和时间都说了。

## 吹牛测试：不用装防吹牛（21:20）

浅华问"现在她还吹牛吗"，用真模型跑了六个典型问题：

| 问 | 工具调用 | 表现 |
|---|---|---|
| 现在几点了 | 无 | 答"晚上七点四十一" ✅（系统时间在 prompt 里） |
| 服务器还活着吗 | memory_search ×4 | **"我手上没有能直接探活的东西"** ✅ 诚实 |
| 明天洛阳天气 | weather ×2 | 查准、报来源 ✅ |
| 今天科技新闻 | 8 次搜索+抓取 | 真查了 ✅ |
| 你刚才查的是什么 | memory_search ×2 | **"我没查，是我编的"** ⚠️ |
| 我家下雨吗 | memory_search + weather | "没存你家在哪，按刚才的洛阳查" ✅ |

**结论：没有"没查说查了"这种吹牛。** 防吹牛系统可以不做。

### 但有一个反向问题

第五问，她上一轮明明调了 8 次工具，却说**"我没查，是我编的"**。

这是**误报**：她的工具记录只在 `raw/tools.jsonl`，既不在记忆里、也不在 prompt 里。
她翻记忆找不到"我查过什么"，就推断自己没查。

**这正是浅华说的"有点矫枉过正"**——她太容易否定自己。

### 怎么修

不是加"防吹牛"（那会更严），而是**让她知道自己做过什么**：

- 工具调用写进记忆（`self_action`，大纲 D12 就是这么设计的）
- 或者当前这一轮的工具调用直接拼进下一轮的上下文

前者是长期（"我上周查过什么"），后者是短期（"我刚才查了什么"）。

现在的缺口是：**短期这条路也没有**。

### 一个附带发现

问"我家那边下雨吗"，她没追问"你家在哪"，直接按上文刚说过的洛阳查，并说明了这个假设。

这个处理是对的——但暴露另一件事：她不知道你住哪，因为**记忆里没有**（还没聊到过）。

## 验收修复：QA → 事实 → 出话的闭环（21:25）

M3 验收指出的第一个问题成立，而且是我之前说错话的地方。

### 我之前说错了什么

M2 收尾我写的是「有结论才写，M3 接上工具后**这条路自动生效**」。

**不成立。** `chat_qa/scene.py` 里的 facts 是硬编码的空数组，工具查到了也不会变成 facts。
之前天气答得对，是因为 **reply 自己又调了一次工具**——qa 查的结果被丢掉了。

实测代价：同一个问题查两遍（qa 一次、reply 一次），每次都多一轮模型调用。

### 改了什么

**1. 查证 prompt 要求结构化输出**

```
先用工具查（weather / web_search / web_fetch），查完只输出一个 JSON 对象：
{"facts": [{"statement": "一句结论", "source": "从哪来的", "confidence": 0.9}],
 "not_found": ["没查到的"]}
查不到就放 not_found，facts 留空数组——别用猜的补
```

**2. 场景里解析 + 两级兜底**

```
模型给了合规 JSON → 用它
否则有工具结果     → 把工具输出当一条结论（来源=工具名，confidence 0.7）
否则              → facts 空，not_found 记问题
```

第二级兜底的意思是：**宁可把工具原文当结论，也不丢已经查到的东西**；
第三级的意思是：**宁可说没查到，也不拿猜的顶**。

**3. 顺带修的**

- `test_blocks_are_known_kinds` 不认「动作」块（我加块时忘了改测试）
- 工具步数耗尽后的收尾调用没进 `calls`——现在记上了，token 和调用次数对得上
- `cli.py status` 会提示"allow 里有但没实现的工具"（现在会报 `ask_dsh`、`qq_do`）

### 教训

「接线了」和「跑通了」是两件事。这次和 M1 那次是同一个毛病：
**通道铺好了，但上游从来没给过数据**。

以后凡是写"自动生效"这种话，必须实际跑一遍看数据落没落。
